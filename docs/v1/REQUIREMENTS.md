# V1 요구사항 — 비금융 OpenDART 기업 리서치

## 1. 목표

V1은 국내 **비금융 OpenDART 공시기업**을 대상으로, 사용자의 자연어 질문에 맞춰 OpenDART의 재무·공시·사업보고서 근거를 조회하고 재현 가능한 계산과 함께 정리하는 리서치 workflow를 제공한다. 상장·비상장 여부는 결과 메타데이터이며, 기업 식별의 제외 기준이 아니다.

목표는 투자 판단을 자동화하는 것이 아니라 기업 조사에 필요한 자료 수집, 수치 비교, 공시 근거 확인 시간을 줄이는 것이다. 매수·매도·목표주가·개인 맞춤 투자 조언은 제공하지 않는다.

## 2. 주요 사용자와 사용 상황

### 주요 사용자

국내 기업 분석 보고서를 작성하거나 검증하는 투자 스터디 구성원과 기업 분석을 시작하는 개인 리서처. 상장기업 분석이 주된 사용 시나리오이며, 비상장 공시기업은 경쟁사·거래처 등 조사 대상이 될 수 있다.

### 대표 사용 상황

사용자는 한 곳 이상 기업의 실적 추세와 재무지표를 같은 기준으로 비교하고, 사업보고서나 기간 내 공시에서 확인할 수 있는 근거를 함께 확인하고 싶다.

### 제품 가정

이 사용자 정의는 현재 제품 가정이다. 실제 사용자 인터뷰나 사용성 검증 전까지는 확정된 시장 수요로 해석하지 않는다.

## 3. 대상과 지원 범위

### 대상 기업

- OpenDART 기업코드 목록에서 식별되는 상장·비상장 기업을 모두 후보·조회 대상으로 한다.
- 재무·사업보고서 분석은 요청 기업·사업연도에 해당 OpenDART 데이터가 실제 존재하는 범위에서만 제공한다. 데이터가 없으면 범위 밖으로 바꾸거나 추정하지 않고 제한을 표시한다.
- 금융·보험업은 V1에서 제외한다. 금융·보험업의 판정은 OpenDART 기업 정보의 업종코드와 공식 산업 분류의 매핑을 데이터 계약 단계에서 검증한 뒤 확정한다.
- 금융업 제외는 기능 축소가 아니라, 은행·보험·증권에 별도 지표·해석·평가가 필요하기 때문이다. 금융업 확장 여부와 시점은 V1 완료 후 별도 결정한다.

### 지원 질문

1. 하나 이상의 기업에 대한 지정 사업연도 재무 수치 조회
2. 하나 이상의 기업에 대한 다년도 재무 추세 및 비교
3. 매출 성장률, 영업이익률, ROA, ROE 등 명시된 계산 지표 분석
4. 기업·기간 조건의 OpenDART 공시 목록과 원문 링크 조회
5. 사업보고서의 위험요인·사업환경 등 원문 근거 검색
6. 재무 추세와 사업보고서 근거를 함께 제시하는 사실 중심 리서치

### 지원하지 않는 질문

- 실시간·과거 주가와 거래량 분석
- 매수·매도·목표주가·포트폴리오 추천
- 공시나 사업보고서의 내용이 주가·실적 변동의 원인이라는 단정
- 금융·보험업 전용 재무 분석

## 4. 입력 계약

| 입력 | 설명 | V1 처리 원칙 |
|---|---|---|
| 기업명 | 한 곳 이상의 기업명 | 전체 기업코드 목록에서 후보를 만든다. 동명이거나 모호하면 정식명, `corp_code`, 상장 구분·종목코드(있는 경우)를 제시해 확인을 요청하고, 선택 뒤 조회한다. |
| 기간 또는 사업연도 | 명시 연도·연도 범위·최근 N개 사업연도 | 명시 연도를 우선한다. 최근 N년은 실제 사업보고서 가용 데이터를 기준으로 정한다. 다기업이면 공통으로 비교 가능한 사업연도를 선택하고 선택 근거를 남긴다. |
| 분석 요청 | 재무, 계산, 공시 목록, 사업보고서 근거 또는 복합 요청 | 질문을 구조화하고 필요한 Tool만 조건부로 실행한다. |

## 5. 데이터와 계산 기준

### 데이터 원천과 보고서 기준

- 데이터 원천은 OpenDART다.
- 재무 데이터는 사업보고서(`reprt_code=11011`)의 연간 재무제표를 기준으로 한다.
- 연결재무제표(CFS)를 우선 사용한다. 해당 기업·사업연도에 연결 값이 없을 때만 별도재무제표(OFS)를 사용하고, 결과에 기준을 표시한다.
- 한 기업·사업연도의 비교·계산에서 연결과 별도 계정을 섞지 않는다.
- 기간 공시 목록은 사용자가 요청한 경우에만 제공하며, 최종 제출본 정책과 접수번호·원문 링크를 함께 기록한다.

### 원천 재무 항목

매출액, 영업이익, 당기순이익, 자산총계, 부채총계, 자본총계, 유동자산, 유동부채, 영업활동현금흐름.

### 계산 지표

매출 성장률, 영업이익률, 순이익률, ROA, ROE, 부채비율, 유동비율, 영업현금흐름률.

계산식·계정 매핑·단위와 분모가 0 또는 음수인 경우의 처리 규칙은 데이터 계약·계산 평가에서 확정한다. LLM은 원천 수치나 계산 결과를 만들지 않고, 검증된 결과를 설명하는 역할만 맡는다.

## 6. 결과 계약

V1 결과에는 아래 요소가 있어야 한다.

| 결과 요소 | 필수 내용 |
|---|---|
| 리서치 요약 | 질문에 대한 사실 중심 설명과 비교 범위 |
| 재무 근거 | 기업명, 사업연도·결산일, 계정명, 원천 수치, 연결·별도 기준 |
| 기업 식별 근거 | 확정 `corp_code`, 상장 구분·종목코드(있는 경우), 또는 후보 확인·미확정 사유 |
| 계산 근거 | 계산식, 입력 수치, 결과 값, 계산 불가·주의 사유 |
| 공시·문서 근거 | 공시명, 접수일, 접수번호, 원문 링크 또는 사업보고서 문단 근거 |
| 실행 경로 | 사용한 Tool과 조회·계산·검색 단계 |
| 한계·실패 | 누락 데이터, 비교 제약, 근거 부족, 지원하지 않는 요청 |

서로 다른 업종의 기업도 수치를 비교할 수 있지만, 산업 특성 차이 때문에 특정 비율만으로 우열이나 투자 적합성을 단정하지 않는다.

## 7. 기능 요구사항

### FR-1. 기업 식별과 대상 판정

- 기업명에서 하나 이상의 OpenDART `corp_code`를 식별한다.
- 상장 여부는 결과 메타데이터로 확인하고, V1 비금융 대상 여부와 요청 데이터 가용성을 별도로 판정한다.
- 식별 실패, 모호한 기업명, 금융업, 데이터 부재는 추측하지 않고 후보 확인 또는 제한 사유를 반환한다.

### FR-2. 기간 해석과 재무 조회

- 명시 연도·연도 범위·최근 N년을 해석한다.
- 다기업 질의에서는 비교 가능한 공통 사업연도를 결정하고, 기업별 결산일·데이터 부재를 결과에 남긴다.
- 지정 기업·사업연도의 사업보고서 재무계정을 조회하고, CFS 우선/OFS 대체 기준을 일관되게 적용한다.

### FR-3. 재무 계산

- 원천 수치를 정규화한 뒤 확정된 공식으로 계산 지표를 산출한다.
- 분모 0·음수, 결측, 비교 불가능한 기준은 계산값을 추정하지 않고 제한을 표시한다.
- 입력 수치·공식·결과를 재현할 수 있어야 한다.

### FR-4. 공시 목록과 사업보고서 근거

- 기업·기간 조건으로 OpenDART 공시 목록을 조회하고 원문 식별자를 제공한다.
- V1은 공시의 중요도를 자동 추정하지 않는다.
- 사업보고서 RAG는 원문 근거가 필요한 질문에서만 실행한다.
- RAG는 별도 retrieval 평가를 통과한 경우에만 최종 workflow에 포함한다.

### FR-5. 질문 해석과 조건부 workflow

- LLM Router는 질문을 기업, 기간, 분석 유형, 필요한 근거 유형으로 구조화한다.
- Graph는 재무·계산·공시 목록·RAG 중 필요한 Node만 실행한다.
- 기업 식별·기간 결정·수치 계산은 LLM의 추측이 아닌 Tool 또는 결정론적 로직으로 처리한다.

### FR-6. 근거와 결과 검증

- 답변 전에는 수치·계산·문서 메타데이터가 연결된 Evidence Packet을 검증한다.
- 답변 후에는 주요 수치와 인용이 제공 근거와 맞는지 검증하는 후보 방식을 평가한다.
- 근거 부족, API 실패, 일부 기업·연도의 누락은 추측으로 보완하지 않고 부분 결과 또는 제한으로 표시한다.

## 8. 비기능 요구사항

- 재현성: 같은 평가 입력, 데이터 기준일, 모델·Prompt·설정에서 결과를 재현할 수 있어야 한다.
- 추적성: 수치·문서·계산에 출처와 실행 정보를 남긴다.
- 안전성: API 키를 결과, 로그, notebook 출력, Git에 노출하지 않는다.
- 성능: 품질이 비열등한 후보끼리만 지연시간, Tool 호출 수, VRAM/RAM, 모델 크기를 비교한다.
- 회귀: 새 Tool·RAG·workflow 경로를 추가하면 기존 end-to-end holdout으로 회귀 평가한다.

## 9. V1 완료 조건

최종 통합 구현을 시작하기 전에는 다음이 충족되어야 한다.

1. 지원 질문·결과 계약·금융업 제외 기준과 상장·비상장 데이터 부재 처리 원칙이 문서화되어 있다.
2. 평가 질문, 정답 수치·계산·문서 근거, 개발/holdout 분리 방식이 합의되어 있다.
3. 데이터 계약, Router·Tool, 기간 Resolver, RAG, Validator, workflow의 평가 계획이 정해져 있다.
4. 실제 후보 비교 결과와 선택·보류 근거가 보고서에 기록되어 있다.

V1을 완료했다고 판단하려면 선택된 단일 workflow가 holdout 평가를 마치고, 실제 질의 결과에 근거·실행 경로·한계를 표시해야 한다.
