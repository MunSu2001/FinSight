# V1 요구사항 — OpenDART 근거 기반 리서치

## 1. 목표

V1은 국내 상장사 한 곳에 대한 재무 추세와 관련 공시 근거를, 조회·계산·출처가 확인되는 리서치 결과로 제공한다.

V1의 목표는 투자 판단 자동화가 아니라 기업 조사에 필요한 첫 자료 수집과 근거 정리의 시간을 줄이는 것이다.

## 2. 주요 사용자와 사용 상황

### 주요 사용자

국내 상장사 분석 보고서를 작성하거나 검증하는 투자 스터디 구성원과 기업 분석을 시작하는 개인 리서처.

### 대표 사용 상황

사용자는 한 기업의 실적 추세를 확인하고, 같은 기간에 참고할 공시를 찾은 뒤 출처가 포함된 메모를 만들고 싶다.

### 제품 가정

이 사용자 정의는 현재 제품 가정이다. 실제 사용자 인터뷰나 사용성 검증 전까지는 확정된 시장 수요로 해석하지 않는다.

## 3. 지원 질문 범위

V1은 아래 범주의 질문만 다룬다.

1. 단일 기업의 사업연도별 매출액, 영업이익, 당기순이익 조회
2. 위 수치로 계산 가능한 매출 성장률, 영업이익률 등의 결정적 지표
3. 지정 기간의 공시 목록 조회와 원문 링크 제시
4. 재무 결과와 공시 근거를 함께 보여주는 사실 중심 리서치 메모

### 대표 질문

> 삼성전자의 최근 3년 매출액과 영업이익률 변화를 정리하고, 같은 기간 참고할 공시를 알려줘.

> SK하이닉스의 2025년 매출액, 영업이익, 당기순이익과 해당 사업연도 사업보고서 링크를 알려줘.

## 4. 입력 계약

| 입력 | 설명 | V1 처리 원칙 |
|---|---|---|
| 기업명 | OpenDART 공시대상회사 정식 명칭 | 현재는 정확한 명칭 일치를 우선 사용한다. 실패 시 조회 불가를 알린다. |
| 기간 또는 사업연도 | 4자리 사업연도 또는 최근 N개 사업연도 | 명시된 연도를 우선한다. 최근 N개 연도는 실행 기준일에 OpenDART 사업보고서가 조회되는 가장 최신의 완료 사업연도부터 계산하며, 그 기준일을 결과에 남긴다. |
| 분석 요청 | 재무 조회, 계산, 공시 근거 요청 | 지원 범주 밖의 요청은 수행하지 않은 범위를 밝힌다. |

## 5. 결과 계약

V1 결과에는 아래 요소가 있어야 한다.

| 결과 요소 | 필수 내용 |
|---|---|
| 리서치 요약 | 질문에 대한 사실 중심의 간결한 설명 |
| 재무 근거 | 기업명, 사업연도, 계정명, 원본 또는 정규화 수치, 데이터 출처 |
| 계산 근거 | 계산식, 입력 수치, 결과 값 |
| 공시 근거 | 공시명, 접수일, 접수번호 또는 원문 링크, 선택 이유 |
| 실행 경로 | 사용한 조회·계산·검색 단계 |
| 한계·실패 | 누락 항목, 조회 실패, 근거 부족 또는 지원하지 않는 요청 |

## 6. 기능 요구사항

### FR-1. 기업 식별과 재무 조회

- 기업명에서 OpenDART `corp_code`를 식별한다.
- 지정 사업연도의 사업보고서(`11011`) 주요 재무계정을 조회한다.
- 연결 재무제표를 우선 사용한다. 연결 값이 없을 때만 별도 재무제표를 대체 사용하고, 결과에 별도 기준임을 명시한다.
- 각 값의 사업연도, 보고서 종류, 연결·별도 기준을 결과에 남긴다.

### FR-2. 다년도 재무 추세와 계산

- 여러 사업연도의 동일 계정을 조회한다.
- 성장률과 영업이익률처럼 공식이 명확한 지표는 Python 계산으로 처리한다.
- LLM은 계산 결과를 설명할 수 있지만 수치 계산의 원천이 되지 않는다.

### FR-3. 공시 근거 검색

- 기업·기간을 조건으로 OpenDART 공시 목록을 조회한다.
- V1의 기본 공시 근거는 사업보고서 원문 링크다. 사용자가 기간 내 공시 목록을 요청한 경우에는 해당 기간의 최종 제출본만 함께 제시하며, 자동으로 중요도를 추정하지 않는다.
- 선택된 공시는 접수일과 원문으로 이동할 수 있는 식별자를 포함한다.
- 사업보고서 원문 RAG는 별도 retrieval 평가를 통과한 경우에만 V1 workflow에 포함한다.

### FR-4. 질문 해석과 workflow 선택

- LLM Router는 지원 질문을 구조화된 작업 요청으로 바꾼다.
- Graph는 필요한 조회·계산·검색 Node만 실행한다.
- Router가 생성한 기업명, 기간, 분석 유형은 후속 Tool 인자와 함께 기록 가능해야 한다.

### FR-5. 근거 검증과 결과 생성

- 주요 숫자와 공시 관련 주장은 데이터 근거 또는 원문 근거를 연결한다.
- 계산 결과는 입력 수치와 계산식을 재현할 수 있어야 한다.
- 근거가 없는 주장, API 실패 또는 데이터 누락은 단일 workflow 내부의 Validator 또는 검증 Node가 결과에 표시한다. 이는 V3의 multi-agent Validator 역할과 별개다.

## 7. 제외 범위

- 둘 이상의 기업 비교
- 실시간·과거 주가와 거래량 분석
- 매수·매도·목표주가·포트폴리오 추천
- 공시나 뉴스가 주가 변동의 원인이라는 인과 판단
- multi-agent orchestration
- 사용자 계정, 저장소, 알림, API 서버, 대시보드

## 8. 비기능 요구사항

- 재현성: 같은 평가 입력, 데이터 기준일, 모델·Prompt·설정에서 결과를 재현할 수 있어야 한다.
- 추적성: 결과의 수치·문서·계산에 출처와 실행 정보를 남긴다.
- 안전성: API 키를 결과, 로그, notebook 출력, Git에 노출하지 않는다.
- 실패 처리: 데이터가 없거나 API가 실패하면 추측하지 않는다.
- 비용·성능: 모델·workflow 비교 시 품질을 먼저 통과한 후보만 지연시간, 메모리, 모델 크기를 비교한다.

## 9. V1 완료 조건

V1 통합 구현을 시작하기 전에는 다음이 충족되어야 한다.

1. 지원 질문 범위와 결과 계약이 사용자와 합의되어 있다.
2. 평가 질문셋과 정답 근거가 준비되어 있다.
3. 재무·계산·공시 검색·Router·근거 검증의 평가 방식이 정해져 있다.
4. 데이터와 모델의 baseline 측정 후 채택 기준을 문서화한다.

V1을 완료했다고 판단하려면 선택한 단일 workflow가 합의된 평가 기준을 통과하고, 결과에 근거·실행 경로·한계가 표시되어야 한다.
