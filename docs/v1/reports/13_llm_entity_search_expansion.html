1. 목적과 가설

사용자 기업명 표현이 줄임말·오타·한글/영문 표기 차이일 때, LLM이 구조화된 검색어 후보를 제안하면 기존의 정규화 exact + 문자열 유사도(fuzzy) 후보 생성보다 정답 OpenDART 기업을 더 많이 후보 집합에 포함할 것이라는 가설을 검증했다.

LLM은 corp_code를 선택하지 않고 검색어만 반환한다. 각 검색어는 OpenDART 기업코드 목록에서 다시 탐색하고, 후보는 corp_code 기준으로 병합한다. 고유 raw exact가 있는 8개 입력은 LLM을 호출하지 않았다.

2. 비교 조건

후보처리역할
A. 기준선원문 기업명으로 OpenDART 정규화 exact와 fuzzy 후보를 병합LLM 없이 가능한 후보 탐색 기준
B. LLM 확장A 실행 후 고유 raw exact가 없을 때만 Qwen이 최대 2개 검색어를 제안하고, 같은 OpenDART 인덱스로 재탐색·병합LLM 검색어 제안의 추가 이득과 비용 확인

평가 입력은 26개이며, 정답 기업이 있는 사례는 21개다. 정식명, 띄어쓰기, 시장 약칭, 한 글자 오타, 한글 표기, 포괄 표현, 존재하지 않는 가상 기업명을 포함했다. 정답 기업·종목코드는 채점에만 사용했고 LLM 프롬프트나 후보 생성 함수에는 전달하지 않았다.

4. 실패 사례와 원인 해석

기준선이 놓친 5개 정답 사례는 하닉, 엘지전자, 네이버, 포스코홀딩스, 삼바였다. B도 모두 놓쳤다.

18회의 LLM 호출 중, 저장된 결과에서 비어 있지 않은 검색어는 엘지전자와 네이버 두 개뿐이었다. 둘은 입력 원문을 그대로 반복한 형태였고, OpenDART의 정규화 exact 기업명으로 검증되지 않았다. 나머지 호출은 빈 검색어 목록을 반환했다. 단일 확인 사례 하닉도 decision='unknown', 빈 목록을 반환했다.

해석: 이 결과는 “Qwen이 기업명을 절대 해석하지 못한다”는 결론이 아니다. 현재 프롬프트가 불확실하거나 포괄 표현이면 빈 목록을 반환하도록 강하게 제한했기 때문에, 줄임말·오타까지 과도하게 보류한 것으로 해석하는 것이 타당하다. 다만 실제 측정 결과상 이 프롬프트·모델 조합은 안전한 대신 후보 회수 이득이 전혀 없었다.
