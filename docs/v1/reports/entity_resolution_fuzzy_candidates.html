기업 식별: 문자열 유사도 후보 생성 비교

실행일: 2026-09-03 · 데이터: OpenDART 기업코드 목록 118,831건 · 라이브러리: RapidFuzz 3.14.5

1. 목적과 가설

정규화된 이름의 완전 일치 검색만으로는 오타나 일부만 입력한 기업명을 찾을 수 없다. 문자열 유사도 후보 생성을 추가하면 정답 기업이 상위 3개 후보에 포함되는 비율(Candidate Recall@3)이 높아질 것이라는 가설을 확인했다.

이 실험은 후보 생성만 평가한다. 유사도 점수로 기업을 자동 확정하거나 OpenDART API를 호출하지 않는다.

2. 비교 조건

후보처리 방식측정
A. 정규화 인덱스만공백·기호를 제거하고 영문을 대문자로 바꾼 뒤, 정확히 같은 키만 조회Candidate Recall@1/@3, p50/p95 지연시간
B. 정규화 인덱스 + 문자열 유사도정확 일치가 없을 때 RapidFuzz ratio로 이름 키 상위 20개를 탐색하고 기업 후보 3개 반환동일

긍정 사례 8개(정확명, 오타, 부분 표현, 영문 표기, 한글 별칭, 약칭)와 존재하지 않는 기업 1개를 사용했다. 별칭 사전은 비워 두었다.

B는 A보다 Recall@1을 0.375, Recall@3을 0.500 높였다. 다만 전체 기업명 키 218,777개를 문자열 비교하므로 지연시간은 약 26 ms 늘었다. 이 수치는 노트북 프로세스 안에서 10회 반복한 마이크로벤치마크이며, 최종 서비스 전체 지연시간을 뜻하지 않는다.

5. 결정

후보결정이유와 조건
A. 정규화 인덱스만미채택매우 빠르지만 긍정 사례의 25%만 상위 3개에 정답을 포함했다. 정확한 공식명·영문 대소문자 차이 처리에는 유지하되, 단독 후보 생성 전략으로는 부족하다.
B. 정규화 인덱스 + 문자열 유사도조건부 채택오타·부분 표현에서 Recall@3이 0.750으로 개선됐다. 단, 후보 생성 용도로만 사용한다. 한글/영문 별칭과 약칭을 해결하지 못하고 거짓 후보도 반환하므로 자동 기업 확정에는 미채택이다.

6. 한계와 다음 검증 필요사항

  • 긍정 사례가 8개인 개발용 소표본이므로 일반화된 성능 수치가 아니다.
  • 별칭 사전, 상장기업 필터, 점수 임계값, 후보 간 점수 차이 정책은 아직 비교하지 않았다.
  • 따라서 현재 확정된 것은 “문자열 유사도를 후보 생성에 쓸 가치가 있다”는 점뿐이다.
