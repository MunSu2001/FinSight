27. 사업보고서 검색 방식 비교

저장된 노트북 출력 확인: 2026-10-05 · 삼성전자·리노공업 2024 사업보고서 각 1건 · 기본 질문 10개 + 같은 근거의 실제형 재표현 6개

목적: 26번에서 조건부 기준선으로 선택한 제목 경계 우선 청킹(B)을 고정하고, 사업보고서의 정답 근거가 검색 상위에 나타나는지를 어휘·의미 벡터·하이브리드 방식으로 비교한다. LLM 답변 생성 품질은 평가하지 않는다.
간단한 결과·결정: 기본 질문에서는 문자 기반 어휘 검색이 Hit@5 9/10으로 가장 높았다. 실제형 재표현에서는 하이브리드가 4/6으로 가장 높지만, 평균 역순위(MRR@5)는 어휘 검색이 약간 높았다. 의미 임베딩 입력에서 480개 청크 중 2개가 잘렸고 표본도 작으므로 최종 검색기 채택은 보류한다. 다음 비교의 재현 가능한 어휘 기준선으로 현재 문자 검색을 유지한다.

1. 비교 조건

항목조건
원문·청킹26번과 같은 접수번호의 삼성전자 96개, 리노공업 384개 B 청크. 16개 질문의 정답 인용문이 해당 회사 청크에 적어도 한 번 포함되는 것을 확인했다.
어휘문자 2~4-gram HashingVectorizer의 L2 정규화 벡터 유사도. BM25가 아니다.
벡터CPU의 intfloat/multilingual-e5-small 임베딩. 질문 query:, 청크 passage: 접두어 사용.
하이브리드두 검색기의 상위 20개씩을 RRF(k=60)로 결합. 따라서 양쪽 모두 20위 밖인 근거는 후보에 들어가지 않는다.
정답·지표원문 인용문 전체를 공백 제외하고 포함하는 청크의 첫 순위. Hit@3/5와 MRR@5, 질문별 실패 및 질의 시간을 확인한다.

3. 질문별로 무엇이 달라졌나

4. 비용·자원과 해석 한계

이 실행에서 모델 로드는 13.6초, 파라미터 크기는 약 449 MiB였다. 480개 청크의 CPU 임베딩 생성은 회사별 4.94초·18.90초였고, 생성된 dense 행렬은 0.14·0.56 MiB였다. 어휘 인덱스 생성은 0.06·0.14초, 희소 행렬은 0.69·2.36 MB였다. 이 수치는 최초 준비 비용과 인덱스의 저장 크기이며, 전체 프로세스 메모리 사용량이나 반복 측정의 분산은 아니다. 외부 LLM API 비용은 없었다.

리노공업 청크 2개가 E5의 512-token 입력 한계를 초과해 뒤쪽이 잘렸다. 이 잘림이 개별 실패의 원인인지는 확인되지 않았다. 현재 정답 판정은 인용문 전체가 한 청크에 있어야 한다. 의미상 맞는 다른 문장이나 여러 청크를 함께 읽어야 하는 질문은 정답으로 인정하지 못하므로, 최종 답변 품질과 동일시할 수 없다.

5. 채택·미채택

후보현재 결정근거
문자 기반 어휘다음 비교의 기준선으로 유지기본 질문에서 Hit@5·MRR@5가 가장 높고 재표현에서도 MRR@5가 가장 높다. 다만 시설투자·연결대상 질문은 놓친다.
의미 벡터단독 최종안 미채택, 결론 보류일부 재표현 질문은 개선하지만 기본 질문의 Hit@5가 낮고, 입력 잘림이 남아 있다.
하이브리드최종안 보류재표현 Hit@5는 가장 높지만 기본 질문에서는 어휘 단독보다 낮고, 잘림·상위 20개 후보 제한의 영향을 받을 수 있다.

다음 비교에서는 잘리는 청크를 먼저 처리하고, 같은 질문셋에서 BM25를 어휘 후보로 추가할 필요가 있는지 검토할 수 있다. BM25가 더 좋을 것이라고 미리 단정하지 않는다. parent–child 청킹 비교와 최종 답변 평가는 이 보고서의 범위 밖이다.
