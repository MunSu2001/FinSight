25. 사업보고서 원문 추출 비교

사용자 저장 실행 출력 확인: 2026-10-02 · 삼성전자·리노공업의 2024 사업연도 사업보고서

목적: OpenDART의 사업보고서 ZIP에서 XML을 꺼내 텍스트로 정리할 때, 제목·표 경계를 버리는 A와 표시하는 B의 출력 형태와 기본 실행 가능성을 확인한다. 두 후보는 같은 BeautifulSoup lxml-xml 파서를 사용한다. 이는 서로 다른 XML 파서나 RAG 검색 성능의 비교가 아니다.
간단한 결과·결정: 두 보고서 모두 API·ZIP·텍스트 추출 셀에서 저장된 실행 오류가 없고, 출력 예시의 한글은 읽을 수 있었다. 사용자는 제목과 표 경계를 일부 남기는 B를 후속 텍스트 정리 기준선으로 채택했다. A는 기본 정리 방식으로 미채택했다. 원문 전체의 무손실성이나 검색 성능에서 B가 우세하다는 결론은 아니다.

1. 입력과 비교 조건

항목조건
문서 선택2025년 접수일 범위의 사업보고서 최종 제출본 중 보고서명에 2024.12가 있는 문서. 사업연도와 접수연도를 구별한다.
원문공시 목록의 접수번호로 OpenDART document.xml을 호출하고 ZIP 안에서 가장 큰 XML을 실험용 규칙으로 선택한다. 첨부 XML도 존재하므로 이 규칙을 모든 문서의 본문 식별 정책으로 일반화하지 않는다.
고정 조건같은 XML 파일, 같은 BeautifulSoup(..., 'lxml-xml') 파스 트리. LLM·OCR·LlamaIndex·청킹·embedding·retrieval은 실행하지 않음.
Aget_text(' ', strip=True)로 읽을 수 있는 글자를 공백으로 연결해 한 줄로 평탄화.
B같은 파스 트리의 글자를 순회하면서 TITLE/SUBTITLE 앞에 제목 표시, TR에 줄바꿈, TD/TH 사이에 구분자를 추가.

B의 글자 수 증가는 제목·표 표시 문자와 공백 차이를 포함한다. 더 많은 원문을 정확히 추출했다는 뜻이 아니다. 시간은 각 후보의 단일 실행값이며, B가 일반적으로 느리거나 빠르다는 판단 근거가 아니다. 원문 다운로드는 삼성전자 0.24초, 리노공업 0.14초로 기록됐고, ZIP·XML 크기와 메모리 최대 사용량의 전체 비용은 측정하지 않았다. LLM 호출·토큰 비용은 0이다.

3. 출력 해석과 한계

  • 삼성전자 예시에서 B는 주요 제품 표의 부문·제품 셀을 줄과 구분자로 나눠 A보다 사람이 읽기 쉽게 보였다. 제목 예시에는 II. 사업의 내용 등이 확인됐다.
  • 리노공업의 사업의 내용·위험 키워드 첫 일치는 목차였다. 검색 결과가 실제 위험관리 본문을 찾았다는 뜻이 아니며, 목차 잡음은 A/B 모두에 남는다.
  • 두 방식이 같은 XML 파스 트리에서 출발하지만, 원문 전체 텍스트의 누락·중복·순서 보존을 독립적으로 대조하지 않았다. 출력 일부에서 한글 깨짐이 보이지 않은 것과 무손실 추출은 다르다.
  • B의 제목·표 표시가 계층적 청킹이나 retrieval 정확도를 개선하는지는 미측정이다. 이후 청커가 원본 XML 구조를 직접 쓰면 이 중간 텍스트 A/B 차이를 사용하지 않을 수도 있다.
경계: B는 텍스트 표현의 기준선이지 XML 파서·청킹·검색 파이프라인의 최종 채택이 아니다. 특히 ZIP 안의 가장 큰 XML을 본문으로 간주하는 규칙과 본문 누락 가능성은 다른 기업·문서에서 다시 확인해야 한다.

4. 채택·미채택 및 다음 검증

후보결정이유와 조건
A. 한 줄 평탄화기본값 미채택간단하고 이번 예시의 글자는 읽을 수 있지만, 제목·표 경계를 텍스트에 남기지 않는다. 오류 진단이나 단순 기준선으로는 유지할 수 있다.
B. 제목·표 경계 표시후속 추출 기준선 채택동일 원문에서 사람이 확인할 수 있는 구조 표시를 더 남기며, 이번 두 문서에서는 저장된 실행 오류가 없었다. 검색 품질 향상·무손실성은 아직 주장하지 않는다.

별도의 대규모 파싱 평가 단계는 만들지 않는다. 다만 검색용 인덱스에 넣기 전에 문서별 접수번호·선택 XML·비어 있지 않은 본문·대표 본문 위치를 확인하고, 원문 구조의 주요 텍스트가 B에서 누락되지 않았는지 소수의 근거 구간을 대조하는 가벼운 입력 검증을 둔다. 이후 품질 선택은 독립 정답 문단을 가진 질문셋으로 청킹·retrieval 후보의 Recall@K·MRR·nDCG@K를 비교해 결정한다. 이 보고서는 그 지표의 결과가 아니다.

근거: 25번 노트북의 저장된 출력, OpenDART 공시서류원본파일 가이드, Beautiful Soup 공식 문서. 채택 범위는 이번 두 문서의 후속 텍스트 표현 기준선으로 한정한다.
