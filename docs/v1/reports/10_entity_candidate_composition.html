실행일: 2026-09-14. OpenDART 기업코드 목록 조회 시각: 2026-09-14T00:52:55+09:00. 전체 법인 레코드 119,183개, 정규화 이름 키 219,425개를 사용했다.

목적

약칭·한글/영문 표기·오타 때문에 사용자가 의도한 기업이 후보에서 누락되는지 확인한다. 이 평가는 후보 생성 단계만 다룬다. 후보가 여러 개일 때 자동으로 하나를 선택하는 정책은 08번에서 채택한 사용자 확인 정책을 그대로 유지한다.

평가 구성

  • 대표 상장기업 12개, 사용자 입력 29개
  • 단일 의도 입력 26개: 정식명, 띄어쓰기, 약칭, 한글/영문 표기, 한 글자 오타
  • 의도적 모호 입력 3개: 엘지, 현대, 삼성
  • 후보는 OpenDART 기업코드 목록의 법인명·corp_code·종목코드로만 구성
후보방식
A. 현재 exact-first정규화 정확 일치가 있으면 그것만 반환하고, 없을 때만 문자열 유사 후보를 반환
B. exact + fuzzy 통합정확 일치와 문자열 유사 후보를 함께 반환하고 corp_code 기준 중복 제거
C. B + 개발용 별칭B에 삼전·하닉 등의 개발용 별칭 후보를 추가

채택 판단

후보판정근거와 한계
A. 현재 exact-first미채택삼전처럼 정확 일치 법인이 존재할 때 삼성전자 후보가 사라졌다. Candidate Recall도 B보다 낮았다.
B. exact + fuzzy 통합조건부 채택수동 별칭 없이 Candidate Recall이 20/26에서 21/26으로 개선됐고, exact 후보가 fuzzy 후보를 가리는 구조적 문제를 해소했다. 단, 평균 후보 수가 2.93개에서 5개로 늘었고 독립 holdout 검증이 남아 있다.
C. B + 개발용 별칭최종 채택 보류Candidate Recall은 가장 높지만, 별칭 사전이 이 평가 입력과 같은 개발 가정으로 작성됐다. 따라서 이 점수는 미지 표현 일반화 성능이 아니라 사전이 해당 입력을 복구하는지 보여 주는 진단 결과다. 별칭 사전에 없는 독립 holdout으로 재평가해야 한다.

결론과 다음 확인

다음 평가의 기준 후보 생성기는 B로 둔다. 이후에는 B와 “B + 별칭 사전”을 별칭 사전 작성에 사용하지 않은 holdout에서 비교한다. 별칭이 정답 후보 누락을 줄이면서도 모호 표현을 하나의 법인으로 자동 확정하지 않는 경우에만 별칭 정책을 채택한다.
