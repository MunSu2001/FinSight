1. 목적

상장·비상장 OpenDART 기업을 모두 후보로 유지할 때, 유사하거나 중복된 기업명에서 최상위 후보를 자동 선택하는 정책이 안전한지 확인했다. 후보 목록은 OpenDART의 공식 법인명·corp_code·상장 상태·종목코드로 만들며, LLM은 사용하지 않았다.

2. 비교 조건

후보확정 규칙
A. 최상위 후보 자동 선택후보가 하나 이상이면 1위 기업을 즉시 RESOLVED 처리
B. 명확한 정확 일치만 확정정규화 정확 일치 후보가 하나일 때만 RESOLVED; 복수 후보 또는 문자열 유사 후보는 NEEDS_CONFIRMATION 처리

개발 사례는 정확명 2개, 오타·부분 표현·약칭·별칭·존재하지 않는 이름 5개다. 자동 확정이 적절하지 않은 5개 사례는 “자동 선택하지 않음”이 정답이다.

5. 결정

후보결정근거와 조건
A. 최상위 후보 자동 선택미채택Coverage는 1.0이지만 Unsafe Selection Rate가 0.571이다. 기업·재무 데이터를 잘못 조회할 위험이 너무 커서 V1 기본 정책으로 사용할 수 없다.
B. 명확한 정확 일치만 확정채택자동 오선택이 0이고, 보류가 필요한 사례 5개를 모두 보류했다. 단, 사용자 확인 화면에는 “해당 후보 없음 / 정식명으로 다시 입력” 선택지를 제공해야 하며, 후보 생성 품질·NOT_FOUND 점수 기준은 후속 평가로 남는다.

6. 한계와 다음 검증

  • 사례가 7개인 개발용 소표본이므로 일반화된 운영 성능이 아니다.
  • 사용자가 후보 중 하나를 선택한 뒤의 최종 Entity Accuracy는 아직 측정하지 않았다.
  • 별칭·약칭, 점수 cutoff, 후보 간 점수 차이, 존재하지 않는 기업의 NOT_FOUND 판단은 별도 A/B 비교가 필요하다.
  • 비상장 기업의 재무·사업보고서 데이터 가용성은 아직 검증하지 않았다.
