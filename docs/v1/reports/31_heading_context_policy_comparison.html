31. 제목 계층 문맥 반환 정책·예산 비교

실행·저장: Codex, conda skn25 · 완료 시각 2026-10-05T17:08:55.478960+00:00 · 5기업·2024 보고서 5개·개발 질문 30개 · GPU 0 FP32

테스트 목적: 30번 C의 예산 후 0점이 실제 검색 실패인지 구분하고, 같은 제목 계층 검색 결과에서 큰 부모 전체 반환과 검색 조각 우선 보존·직접 제목 확장을 비교한다. 예산 확대와 제한 없는 결과를 함께 확인한다. LLM 답변 정확도 평가나 최종 운영 통합은 아니다.
간단한 결과: 무제한 C-full의 근거 Recall은 1.0000, C-seed-first는 0.8500다. 8,000 E5 토큰에서 C-seed-first는 Hit 26/30, Recall 0.8500, 문맥 중앙값 5,173토큰이다. 같은 예산의 C-full Recall은 0.0000다. 구체적 우열과 근거는 아래 표를 사용하며, 제목 계층 자체를 2,400 제한의 0점으로 탈락시키지 않는다.

C-seed-first같은 C의 상위 5개 작은 검색 조각을 먼저 담고, 예산 안에서 그 조각의 직접 제목 문맥으로 확장. 같은 제목은 병합하며 다른 제목의 같은 문자열은 구분한다.검색 조각·순위는 C-full과 동일. 반환 구성 전체를 변경하며 제목 계층이나 임베딩을 새로 만들지 않는다.

모든 후보의 초기 문맥 선택은 초과 시 중단하고 뒤의 작은 단위로 건너뛰어 보충하지 않는다. 다만 C-full은 부모 전체, C-seed-first는 작은 조각부터 선택하므로 “직접 제목 확장만”의 독립 효과가 아니다. seed-first 확장은 이미 선택한 조각을 잃지 않는 경우에만 허용한다. 제목 소유 관계가 유일하지 않으면 임의 제목을 선택하지 않고 작은 조각을 유지한다.

E5 + Kiwi SQLite FTS5 BM25, 가중치 5:5, 후보 각 20개, RRF 상수 60, 상위 검색 seed 5개를 고정했다. 기업·보고서는 질문마다 지정하며 기업·기간 Router는 평가하지 않는다. A/B/C-full의 검색은 각각 한 번, C-full/C-seed-first의 동일 순위는 다섯 예산에 재사용했다. 새 후보·기존 기준선 모두 GPU 0 FP32로 실행했다.

예산 없음 / 2,400 / 8,000 / 16,000 / 32,000은 E5 토크나이저로 센 비교 조건이다. 실제 운영 LLM의 최대 입력·권장 입력량·청구 토큰이 아니다. 2,400을 합격선으로 쓰지 않는다. 근거 인용문·정답 ID는 scoring에만 사용하고 반환 정책에는 전달하지 않는다.

근거 Recall은 질문별 “온전히 포함된 고정 인용문 ID 수 / 필요한 ID 수”의 평균이다. 단일 질문 25개는 각 1개, 복합 질문 5개는 각 2개다. 모든 근거 질문 수는 Recall=1인 질문 수다. 겹치는 청크에 같은 인용문이 있어도 정답 ID는 중복 집계하지 않는다.

무제한은 작은 검색 상위 5개에서 반환하는 문맥의 예산을 없앤 것이지 검색 후보를 전 문서로 늘린 것이 아니다. 큰 부모는 질문과 관계없는 본문·다른 부모와 겹치는 내용도 포함할 수 있으므로 높은 Recall만으로 더 정밀한 검색 또는 더 좋은 답변이라고 단정하지 않는다. 제한된 인용문 정답이므로 전체 의미 관련성 Precision·nDCG·완전한 본문 Recall은 평가하지 않았다.

이 결과를 쉽게 읽는 방법

토큰 제한을 높이면 C-full이 회복되는가? 그렇다. 2,400·8,000에서는 근거 Hit가 0/30이지만, 16,000에서는 10/30, 32,000에서는 19/30, 제한 없음에서는 30/30이다. 따라서 30번의 C 0점은 제목 검색 전체를 탈락시킬 근거가 아니다. 8,000에서 일부 문맥은 반환됐어도 알려진 정답 근거가 없어 Hit가 0이었다. “반환 문맥이 모두 비었다”와 구분한다.

문맥을 무조건 많이 넣으면 더 좋은가? 이번 실험으로 최종 답변의 우열은 알 수 없다. C-full은 무제한에서 모든 근거를 포함하지만 문맥 중앙값 36,889토큰·최대 908,791토큰이다. 큰 부모의 겹치는 내용도 포함한 수치라 고유 문서 길이가 아니다. 실제 모델이 긴 문맥을 읽고 정확하게 답하는지, 운영 모델 입력 한도에 맞는지는 미검증이다.

새 C-seed-first는 어떤가? 2,400부터 무제한까지 모든 조건에서 Hit 26/30, Recall 0.85, 모든 근거 회수 25/30으로 동일했다. 예산을 늘리면 문맥량은 늘지만 알려진 정답 근거는 추가되지 않았다. 2,400에서도 LG생활건강 복합 질문 M_L의 두 근거를 모두 담아 A의 Recall 0.5보다 높았다. 전체 A 대비 개선은 이 한 근거에 따른 0.016667 차이로, 광범위한 성능 우위라고 과장하지 않는다.

C-seed-first는 단일 질문 22/25, 복합 질문 Hit 4/5·Recall 0.70이다. 무제한에서도 R01·L01·H04·M_H는 근거를 못 담고 M_R은 두 근거 중 하나만 담았다. 이들은 작은 검색 조각·직접 제목 문맥의 범위 문제를 포함하며, 토큰 예산만 더 키워서는 회복되지 않았다. C-full의 넓은 부모에는 이 근거들이 포함됐으므로 원문에 정답이 없는 사례는 아니다.

현재 권장: C의 제목 계층은 후보로 유지하고 C-seed-first를 A와 함께 실제 답변 평가의 우선 후보로 둔다. C-full은 근거 회수 상한 참고 후보로 남긴다. 제한된 개발셋에서 입력량 대비 근거 회수를 확인한 것이며, 2,400이나 seed-first를 최종 운영값으로 자동 채택하지 않는다. 토큰값을 더 촘촘히 튜닝하는 것보다 실제 답변의 누락·근거 지원을 확인하는 것이 다음 판단에 더 직접적이다.

6. 속도·비용·GPU 자원

  • 실행 전체 wall time: 162.06초. notebook 실행·모델 준비·다운로드·평가를 포함하며 사용자 질의 하나의 지연시간이 아니다.
  • E5 GPU 색인 신규 텍스트 3,772개, 후보 합산 구성 시간 10.25초. 후보 사이 동일 텍스트 임베딩을 재사용했으므로 후보별 cold 속도 우열은 판단하지 않는다.
