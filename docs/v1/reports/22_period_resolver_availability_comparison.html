22. 기간 Resolver 가용성 정책 비교

실행일: 2026-10-01 · 기준연도: 2026 · OpenDART 사업보고서(11011) · 5개 개발 사례

결론: B를 다음 재무 Tool 평가의 조건부 기간 정책으로 채택한다.
사업보고서가 없는 2026년을 명시한 요청에서 B는 연도를 선택하지 않고 LIMITATION을 반환했다. A는 2026년을 선택한 뒤 PARTIAL로 표시했다. 다른 4개 사례에서는 두 후보가 같은 연도를 선택했다. 따라서 이 결과가 보여 주는 B의 이점은 데이터 부재를 명확히 알리는 처리이며, 과거 공시가 빠진 구간에서 더 나은 연도를 찾는 능력은 아직 비교되지 않았다.

1. 목적과 비교 조건

사용자의 최근 N년 또는 명시 연도 요청을 OpenDART에서 실제로 조회할 사업연도로 바꾸는 정책을 비교했다. 여기서 Resolver는 기간을 연도 목록으로 결정하는 코드다. 이번 노트북은 LLM을 호출하지 않았으며, Tool 선택·계산·최종 답변도 평가하지 않았다.

평가셋은 삼성전자, SK하이닉스, 에이피알, 리노공업을 사용한 5개 요청이다. 정답 상태는 실행 전에 노트북에 기록했다. 두 후보는 동일한 OpenDART 조회 결과 캐시를 공유하므로 데이터 조건은 같지만, 실행 순서상 후보별 지연시간 비교는 할 수 없다.

3. 호출 시간과 자원

저장된 로그에는 고유한 기업·연도 확인 11건이 있다. 그중 리노공업 2024년과 삼성전자 2026년은 CFS의 013 뒤 OFS까지 확인했으므로, 코드 경로상 재무제표 API 요청은 13회다. 기업코드 조회는 기업별 캐시를 사용했다. LLM 호출·토큰 비용은 0이고, OpenDART의 별도 과금액은 측정하지 않았다.

기록된 기업·연도 확인 시간은 약 130~2,717ms다. 최초 기업 조회에는 기업코드 ZIP 다운로드 시간이 포함되고, 두 후보는 조회 캐시를 공유했다. 따라서 이 로그로 A와 B의 운영 지연시간 우열을 판단하지 않는다. 메모리·CPU 사용량도 측정하지 않았다.

4. 채택·미채택 이유와 다음 확인

후보판정근거와 남은 조건
B. 가용성·공통연도 기준조건부 채택요청한 연도에 데이터가 없을 때 LIMITATION을 반환했고, 5개 사례에서 잘못된 연도 선택이 없었다. 실제 과거 누락 연도·공통 연도 부족·API 장애 상황은 이후 재무 Tool 평가에 포함해야 한다.
A. 달력 기준 그대로 사용미채택P05에서 조회 불가능한 2026년을 선택하고 필요한 제한 상태를 반환하지 못했다. 다만 A에 별도 가용성 확인 단계를 추가한 대안은 이번에 평가하지 않았으므로 그 대안까지 열등하다고 판단하지 않는다.

다음 재무 Tool 평가에서 실제 공시 이력이 끊긴 연도와 다기업 공통연도 부족 사례를 한 번에 포함해 B의 탐색 이점을 확인한다. API 오류와 데이터 부재를 구분하는 실패 경로도 확인한다. 이 다섯 사례만으로 V1 전체의 기간 처리 성능이나 사용자 질문 해석 품질을 확정하지 않는다.
