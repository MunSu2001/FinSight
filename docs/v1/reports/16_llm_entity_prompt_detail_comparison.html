1. 목적과 후보

15번에서 안정화한 reasoning=False + schema grounding 조건에서, 약칭·오타·한글/영문 표기 변환 실패가 Prompt의 구체성 부족 때문인지 확인했다. LLM은 검색어 가설만 제안하고, 기업 또는 corp_code를 확정하지 않는다.

후보Prompt 내용
A. V15 기준 Prompt역할, 약칭·오타·표기 차이의 기본 처리, 모호 표현 보류, 금지 항목을 짧게 정의한 15번 원문
B. 상세 정책 Prompt호출 조건, 검색 가설의 역할, 약칭·오타·음역/영문 표기 판단, 원문 반복 제한, 모호·무근거 표현 보류, 금지 규칙, JSON 출력 계약을 단계적으로 명시

평가 정답이나 직접 매핑은 B Prompt에 넣지 않았다. 따라서 하닉 → SK하이닉스 같은 정답을 Prompt가 미리 알고 있는 상태의 비교는 아니다.

3. 사례별 해석

B의 추가 회수: A는 네이버를 그대로 제안해 OpenDART의 NAVER를 찾지 못했다. B는 네이버와 NAVER를 함께 제안하여 정답 후보를 회수했다. 기존의 엘지전자 → LG전자 회수도 유지했다.

여전히 실패: B도 하닉을 하닉시스템, 하닉으로 제안해 SK하이닉스를 찾지 못했다. 포스코홀딩스는 표준 표기 POSCO홀딩스로 바꾸지 못했고, 삼바는 ambiguous로 보류했다.

회귀 사례: A는 현차에서 현대자동차를 제안했지만 B는 unknown으로 보류했다. raw fuzzy 기준선이 이미 현대자동차 후보를 포함해 최종 Candidate Recall은 낮아지지 않았지만, 상세 Prompt가 모든 약칭 해석을 일관되게 개선한 것은 아니다.

4. 채택·미채택 판단

조건부 채택: B. 상세 정책 Prompt
Candidate Recall과 LLM 신규 기여가 A보다 높았고, 안전 보류·구조화 출력·출력 계약을 모두 유지했다. 따라서 다음 API 모델 비교의 로컬 기준 Prompt로 사용한다.

미채택: A. V15 기준 Prompt
A는 안정적으로 동작하지만 같은 모델·후처리 조건에서 B보다 정답 후보를 하나 적게 회수했다. 최종 Prompt가 아니라 비교 기준선으로만 보존한다.

최종 채택 보류: B의 개선은 21개 정답 사례 중 1건뿐이며, 하닉·포스코홀딩스·삼바와 현차 회귀가 남아 있다. 이 개발 평가만으로 최종 pipeline Prompt를 확정하지 않는다.

5. 한계와 다음 비교

  • 이 결과는 로컬 qwen3.6:27b 한 모델과 개발용 26개 사례에 한정된다. Prompt의 일반화 성능은 독립 holdout에서 다시 확인해야 한다.
  • 상세 Prompt와 모델 지식의 한계는 완전히 분리되지 않는다. 남은 실패 표현을 API 모델이 더 잘 처리하는지는 같은 Prompt B와 같은 사례로 비교해야 한다.
  • API 모델 연결은 제공처, 인증 방식, 호출 가격, 입력·출력 데이터 보존 조건을 사용자에게 먼저 보고하고 승인받은 뒤 진행한다.
  • LLM이 후보를 넓힐 뿐 최종 기업 선택은 OpenDART 검증과 사용자 확인 정책이 담당한다. 따라서 이 결과만으로 자동 선택 정책을 완화하지 않는다.
