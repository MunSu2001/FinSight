1. 평가 대상과 고정 정책

독립 holdout 36개와, 이미 알려진 보호 그룹명 정책의 회귀 확인 4개를 분리했다. 최종 품질 지표는 독립 holdout 36개만으로 계산했다. OpenAI는 검색어 가설만 제안하며, 제안된 후보는 OpenDART 목록에서 검증한 뒤에도 자동 확정하지 않는다.

사용자 기업 표현
→ OpenDART raw exact + fuzzy 후보
→ 고유 raw exact면 RESOLVED
→ 그 외에는 OpenAI 검색어 가설 + OpenDART 재검증
→ LLM 후보가 있거나 fuzzy 최고점이 75 이상이면 NEEDS_CONFIRMATION
→ 그렇지 않으면 NOT_FOUND

3. 주요 사례 해석

회수 실패: 엔시소프트의 현재 OpenDART 법인명은 NC다. 모델은 엔씨소프트, NCSoft를 제안했지만 현재 법인명 NC을 제안하지 않아 정답 후보를 만들지 못했다. 변경 전 법인명과 현재 법인명의 연결은 별도 별칭·이력 데이터 또는 후보 정책의 평가 대상이다.

숫자 접미사 재확인: 한미반도체2051, 디비하이텍2051, 에스오일2051, 현대제철2051, 코웨이2051, 크래프톤2051은 실제 기업명에 숫자가 붙은 입력이다. 모두 정답 후보를 포함한 NEEDS_CONFIRMATION이 됐다. 이 경우 실제 기업을 자동 확정하는 것보다 “해당 기업을 의미했는지” 재확인하는 것이 의도된 UX다.

OpenDART 기준 가상명: 푸른바다테크2042, 제타오로라홀딩스2051은 평가 시점 OpenDART 기업 목록에 없어, 모델도 검색어를 제안하지 않고 NOT_FOUND로 처리했다.

레이블 검증에서 드러난 데이터 변화: 실행 전 OpenDART 목록으로 정답을 검증하는 과정에서 이전 명칭인 엔씨소프트, 한국항공우주산업, 한라홀딩스 대신 현재 법인명 NC, 한국항공우주, HL홀딩스을 사용하도록 사례를 수정했다. 동일 명칭이 여러 법인에 존재한 동원산업, 현대엔지니어링은 단일 정답 사례로 쓰지 않았다.

S-OIL 레이블 한계
S - OIL은 기대 상태를 RESOLVED로 설정했지만 현재 OpenDART raw exact 후보가 소일산업과 S-Oil 두 건이었다. 실제 정책의 NEEDS_CONFIRMATION은 안전한 동작이지만, 이 한 건은 사후 확인으로 드러난 레이블 오류다. 이 실행의 State Accuracy와 LLM Call-path Accuracy에는 그대로 반영되어 있으며, 결과를 본 뒤 수정하면 독립 holdout이 아니라 새 validation이 된다.

4. 현재 판단과 한계

최종 운영 정책 선정 보류
이번 결과는 현재 후보 생성·재확인 구조를 반대할 근거를 만들지 않았다. 다만 NOT_FOUND 사례가 두 개뿐이고, 변경 전 법인명 엔시소프트 → NC를 놓친 사례도 있다. 최종 채택 여부는 사용자가 이 한계와 이후 비교 범위를 판단한 뒤 결정한다.

유지 가능한 안전 경계: LLM은 검색어만 제안하며, OpenDART 검증과 사용자 확인 없이 corp_code를 확정하지 않는다. 이번 실행에서 자동 오선택은 없었다.

다음 비교 후보
실제 운영에서 NOT_FOUND 정책을 더 강하게 검증하려면, OpenDART 기준으로 후보가 없고 특정 실기업을 의도했다고 보기 어려운 입력을 더 많이 수집해야 한다. 이 비교 범위는 사용자 결정 후 새 개발 validation과 독립 holdout으로 분리한다.

5. 한계와 재현 정보

  • OpenDART 법인명은 변경될 수 있다. 정답 법인명·corp_code는 실행 시점의 목록에서 사전검증했고, 목록 조회 시각은 노트북 출력에 기록됐다.
  • 사용자 확인 뒤 어떤 후보를 선택했는지는 오프라인 holdout에 포함되지 않는다. 따라서 실제 최종 Entity Accuracy는 아직 측정하지 않았다.
