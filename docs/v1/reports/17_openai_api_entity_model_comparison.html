1. 목적과 비교 범위

로컬 Qwen이 해결하지 못한 약칭·한글/영문 표기 변환이 API 모델에서 개선되는지 확인했다. LLM은 기업이나 corp_code를 고르지 않고 검색어 가설만 반환한다. 제안된 검색어는 다시 OpenDART 목록에서 검증하고, 새로 나온 후보는 자동 확정하지 않는다.

두 제공처는 구조화 출력 전달 방식도 다르므로, 이 결과는 순수 파라미터 수 비교가 아니라 모델·제공처·구조화 출력 조합 비교다.

3. 사례별 해석

API가 추가로 회수한 세 사례: 하닉 → SK하이닉스, 포스코홀딩스 → POSCO홀딩스, 삼바 → 삼성바이오로직스다. Qwen은 각각 하닉시스템·하닉, 포스코홀딩스, 빈 목록을 반환해 정답 후보를 만들지 못했다.

공통으로 회수한 사례: 삼성전쟈 → 삼성전자, 하이닉스 → SK하이닉스, 현대차/현차 → 현대자동차, 엘지전자 → LG전자, 네이버 → NAVER다. 단, raw fuzzy 기준선에 이미 정답이 있던 사례는 LLM의 신규 기여와 구분했다.

중요한 안전 해석: API가 Samsung Electronics, SK Hynix처럼 OpenDART exact에 바로 없는 영문 표현도 일부 함께 제안했다. 최종 기업 선택 권한을 LLM에 주면 안 되는 이유다. 현재처럼 OpenDART 후보 검증과 corp_code 병합, 필요 시 사용자 재질문이 남아 있어야 한다.

5. 채택·미채택 판단

조건부 채택: B. OpenAI API (gpt-5.6-luna)
Candidate Recall, LLM Candidate Recall, LLM 신규 기여, exact 검색어 유효성이 모두 Qwen보다 높았고, 안전 보류·구조화 출력·출력 계약은 낮아지지 않았다. 정확도를 우선하는 현재 기준에서 다음 기업 식별 정책 평가의 모델 후보로 사용한다.

미채택: A. Local Qwen (qwen3.6:27b)
구조화 출력과 안전 보류는 안정적이고 API 과금도 없지만, 개발 사례에서 하닉·포스코홀딩스·삼바를 놓쳐 API보다 Candidate Recall이 낮았다. 최종 운영 모델 후보에서는 보류한다.

최종 모델 선정은 보류: 이 평가는 26개 개발 사례 한 번의 실행이다. API 후보를 확정하려면 개발에 쓰지 않은 독립 holdout에서 기업 식별 전체 정책을 다시 검증해야 한다. API의 p95 지연시간과 실제 운영 비용도 그때 함께 재측정한다.
