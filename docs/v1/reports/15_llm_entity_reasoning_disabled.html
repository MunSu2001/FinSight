1. 목적과 비교 조건

14번의 기본 thinking 구조화 호출은 장시간 완료되지 않아 후보 품질을 평가하지 못했다. 이번 실험은 모델·temperature·26개 사례를 유지한 채 reasoning=False와 JSON Schema의 프롬프트 명시를 함께 적용했을 때, 안정적으로 구조화 출력을 만들면서 기업 후보 회수율을 높일 수 있는지 확인했다.

후보처리의미
A. 기준선사용자가 입력한 원문 기업 표현으로 OpenDART 정규화 exact와 fuzzy 후보를 생성LLM 없이 가능한 기본 후보 집합
B. reasoning-off 확장A를 만든 뒤 고유 raw exact가 아닌 입력에만 LLM이 최대 두 검색어를 제안. 각 검색어를 OpenDART에서 다시 탐색해 A와 병합LLM은 검색어 가설만 제안하며 corp_code를 확정하지 않음

정답 기업명·종목코드·기대 행동 라벨은 채점에만 사용했고 LLM 프롬프트에는 전달하지 않았다. 이번 결과는 reasoning=False + schema grounding의 결합 조건 평가다. 두 변경 중 어느 하나만의 효과를 분리해 증명한 실험은 아니다.

3. 사례 해석

개선한 사례: 엘지전자에서 A는 정답 LG전자를 후보에 넣지 못했지만, B는 LG전자를 제안해 정답 후보를 회수했다. 이것이 B의 유일한 신규 기여다.

계속 놓친 사례: 하닉은 하닉, 하닉홀딩스를 제안해 SK하이닉스를 회수하지 못했다. 네이버과 포스코홀딩스는 입력을 사실상 반복해 OpenDART의 표준 표기(NAVER, POSCO홀딩스)로 바꾸지 못했다. 삼바는 unknown으로 보류해 삼성바이오로직스를 회수하지 못했다.

검색어 품질의 주의점: 삼전 → 삼전, 삼전산업, 엘지전자 → LG전자, 엘지전자처럼 유효한 검색어와 검증되지 않은 검색어가 섞여 나왔다. 따라서 B는 후보를 넓히는 역할까지만 허용해야 하며, LLM 제안만으로 특정 기업이나 corp_code를 자동 확정하면 안 된다.

4. 채택·미채택 판단

조건부 채택: B. reasoning-off + schema grounding
기본 thinking 조건과 달리 18개 호출이 모두 완료·파싱됐고, A보다 Candidate Recall이 1건 높으며 대상 부재 입력도 5/5 안전 보류했다. 따라서 이후 Prompt 또는 모델 후보를 비교할 때 사용할 LLM 검색어 확장 조건으로 유지한다.

유지: A. OpenDART exact + fuzzy 기준선
A는 LLM이 실패하거나 timeout일 때에도 항상 동작하는 필수 fallback이다. B의 개선폭이 1/21에 그치므로 A를 대체하거나 B를 최종 통합 pipeline에 넣는 결정은 아직 하지 않는다.

최종 채택 보류: 이번 실험만으로 “로컬 Qwen 기반 LLM 확장이 충분하다”고 결론 내릴 수 없다. 평가셋은 개발용 26개뿐이고, 두 설정 변경을 함께 적용했으며, 핵심 약칭·한글 표기 실패가 남아 있다.

5. 한계와 다음 비교

  • 다음 Prompt 후보는 하닉·삼바 같은 명백한 시장 약칭과 네이버·포스코홀딩스 같은 한글/영문 표기 변환을 더 잘 제안하도록 비교해야 한다.

  • 최종 선택 전에는 Prompt 작성에 사용하지 않은 독립 holdout과, 필요하면 API 모델을 포함한 모델 비교에서 Candidate Recall, 안전 보류, 오제안 비율, p50/p95를 다시 측정해야 한다.
