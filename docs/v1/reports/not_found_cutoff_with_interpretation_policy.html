V1 기업 식별: C 정책 기반 NOT_FOUND cutoff 비교

실행일: 2026-09-14. OpenDART 기업코드 레코드 119,183개와 정규화 이름 키 219,425개를 사용했다.

목적

11번에서 조건부 채택한 C 정책을 고정한 뒤, exact·명시적 해석·포괄 표현에 해당하지 않는 fuzzy 후보를 언제 NOT_FOUND로 처리할지 비교한다.

C 정책에서 cutoff가 적용되는 위치

동명·포괄 표현 → NEEDS_CONFIRMATION
명시적 별칭·오타 정정 → RESOLVED_INTERPRETED
고유 exact → RESOLVED
그 외 fuzzy 후보 → cutoff 비교 → NOT_FOUND 또는 NEEDS_CONFIRMATION

따라서 삼성전쟈, 하닉, 삼전 같은 보호 입력은 cutoff와 무관하게 기존 상태를 유지해야 한다.

평가 구성

  • 보호 입력 11개: exact 1개, 명시적 해석 6개, 포괄·동명 재질문 4개
  • 미등록 fuzzy 유효 오타 4개: 삼성전저, 카카오오, 현대자동챠, POSCO홀딩수
  • 현재 OpenDART 이름 인덱스에 exact가 없는 synthetic no-match 6개

결론: 현재 근거는 cutoff 70–75 범위를 지지한다. 그러나 두 값 사이의 점수 사례가 없어 어느 하나를 최종 운영값으로 확정할 수는 없다. 초기 통합 구현 전 또는 운영 로그가 쌓인 뒤 추가 입력으로 재평가해야 한다.

한계

대상 부재 6개는 OpenDART 이름 인덱스에 exact가 없는 synthetic no-match이며, 실제 사용자 오입력 전체를 대표하지 않는다. 또한 fuzzy 유효 오타 4개는 개발용 수동 사례다. 이번 결과는 초기 cutoff 후보 범위를 좁히는 근거이지, 모든 기업명 표현에 대한 보장이나 최종 운영 threshold의 확정 근거는 아니다.
