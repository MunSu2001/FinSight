목적

사용자 기업명 표현을 OpenDART 상장 종목코드와 corp_code 후보로 연결할 때, 현재의 정확 법인명 일치 방식의 한계를 확인하고 정규화·제한된 별칭·상장 종목 우선 후보와 비교한다.

해석

  • 기준선 A는 정확한 법인명 3건만 자동 선택했다. 공백·대소문자·별칭 입력은 후보를 찾지 못했고, 셀트리온은 후보 목록에 정답 종목코드가 있었지만 동일 법인명 2건을 이유로 보류했다.
  • 후보 B는 개발 사례에서 모든 정답을 후보에 포함하고 안전하게 선택했다. SK 하이닉스, 현대 자동차, naver, 네이버, 셀트리온을 처리했다.
  • 후보 B가 느린 이유는 매 질의마다 118,831개 레코드의 한글·영문 법인명을 파이썬에서 정규화·전수 탐색하기 때문이다. 모델 지연시간이나 OpenDART 네트워크 호출 시간은 아니다.

판단

정확 일치 기준선 A는 실제 사용자 입력 변형을 처리하기에 부족하므로 최종 후보에서 제외한다. 후보 B는 다음 기업 식별 비교의 기준 후보로 유지한다.

후보 B를 최종 채택하지는 않는다. 별칭 사전에 직접 추가한 네이버 → NAVER를 같은 개발 사례에서 평가했으므로, 별칭 일반화 성능을 증명하지 못한다.

한계와 다음 검증

  • 별칭 사전 작성에 쓰지 않은 holdout 사례가 없다.
  • 존재하지 않는 기업 보류 사례가 1건뿐이다.
  • 실제로 상장 후보가 여러 개인 입력에서 자동 보류하는지 확인하지 못했다.
  • V1 대상 상장 여부는 stock_code만으로 확정하지 않는다. 후속 단계에서 기업개황 API의 corp_cls가 Y/K/N인지 확인한다. 기업개황 API 개발가이드
  • 다음 비교에서는 정규화 인덱스를 한 번 생성하는 후보와 유사도 기반 후보 검색을 추가한다. 품질이 비열등한 경우 p50/p95 지연시간과 메모리 사용량으로 선택한다.
