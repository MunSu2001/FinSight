기업 식별 인덱스 성능 비교 결과

목적

정규화·별칭·상장 종목 우선이라는 동일한 기업 식별 규칙에서, 질의마다 기업코드 전체를 전수 탐색하는 방식과 시작 시 이름 인덱스를 생성하는 방식의 품질·지연시간·메모리 비용을 비교한다.

해석

  • 두 방식은 후보 개수뿐 아니라 후보 corp_code 전체와 최종 선택 corp_code까지 동일했다. 인덱스는 검색 규칙을 바꾼 것이 아니라, 같은 검색 결과를 미리 정리해 둔 것이다.
  • 인덱스 탐색의 질의 지연시간은 이 microbenchmark에서 전수 탐색보다 약 160,000배 낮았다. 다만 이는 기업 식별 함수만 측정한 값이며, 실제 사용자 요청 전체 시간이나 OpenDART API·LLM 시간의 개선 배율은 아니다.
  • 인덱스는 시작할 때 약 0.77초와 Python 할당 peak 약 84.83MiB를 추가로 사용한다. 전수 탐색 대비 한 질의당 약 207ms를 아끼므로, 약 4회 이상의 질의를 처리하면 이 시작 비용을 시간 관점에서 회수한다.

판단

동일한 정규화·별칭 규칙을 유지하는 기업 식별 실행 방식으로는 정규화 인덱스 탐색을 채택한다. 품질 저하 없이 질의 지연시간이 명확히 낮기 때문이다.

한계와 다음 검증

  • 이 선택은 검색 실행 방식에 한정된다. 별칭·오타·약칭을 얼마나 잘 처리하는지는 아직 확정하지 않았다.
  • 개발 사례에 직접 추가한 네이버 → NAVER 별칭이 포함돼 있어 일반화 성능을 증명하지 못한다.
  • 실제 복수 상장 후보, 과거 사명, 오타, holdout 사례가 필요하다.
  • 인덱스의 실제 지속 RAM과 애플리케이션 cold start는 통합 구현 또는 운영 벤치마크에서 별도 측정한다.
