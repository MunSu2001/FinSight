29. 확대 개발셋에서 E5·BM25 결합 가중치 비교

저장 출력 확인: 2026-10-05 · 실행 기록: 2026-10-05 12:50:38 UTC · 코드 기준 커밋 e604c3a · 개발 질문 25개

테스트 목적: E5 벡터 검색과 Kiwi BM25 검색을 함께 사용할 때 어느 결합 비율이 정답 근거를 더 잘 찾는지 확인한다. 28번의 2기업·10질문에서 5기업·25질문으로 넓히고, 같은 청크와 검색 결과에서 가중치만 바꿨다. 청킹 방식, 임베딩 모델, 구조화 SQL 검색, LLM 답변 품질을 비교한 실험은 아니다.
간단한 결과: 벡터:BM25 5:5가 Hit@5 22/25(88%), 알려진 근거 청크 Recall@5 0.79로 가장 높았다. 반면 BM25 단독은 MRR@5 0.5913으로 가장 높지만 Hit@5는 18/25(72%)다. 누락을 줄이는 성능과 첫 근거 순위의 승자가 다르므로 최종 채택은 보류한다. 다음 청킹 비교에 5:5를 임시 기준선으로 사용하는 것은 제안이며, 사용자 승인 전 확정 정책이 아니다.

1. 목적·가설·고정 조건

가설은 두 검색기의 상호 보완으로 단독 검색보다 많은 질문에서 근거를 찾을 수 있다는 것이다. 반대로 부적절한 결합은 한 검색기가 잘 찾은 근거를 뒤로 밀 수 있다. 평균 성능과 개별 실패를 함께 확인한다.

공통 재사용한 질문의 E5·BM25 순위를 한 번씩 계산하고 다섯 비율에 재사용했다. 임베딩 입력에 정답 인용문은 넣지 않았다.

Hit@5는 상위 5개에 알려진 근거가 하나라도 있는 질문 비율이다. 5:5는 두 단독 방식보다 각각 4문항, 16%p 높다. MRR@5는 첫 근거의 역순위를 평균한다. 1위는 1, 2위는 0.5, 상위 5개 실패는 0으로 계산한다. BM25 단독의 1위 적중은 13문항, 5:5는 9문항이라 BM25는 더 자주 놓쳐도 MRR이 높다.

Recall@5는 질문별로 “상위 5개에서 찾은 정답 청크 수 ÷ 알려진 전체 정답 청크 수”를 계산한 뒤 평균한다. 같은 인용문이 여러 청크에 있으면 모두 알려진 정답으로 센다. 따라서 Hit@5 0.88과 Recall@5 0.79는 모순이 아니다. 문서의 의미상 관련 근거를 모두 주석화한 완전한 Recall은 아니다.

3:7은 5:5보다 MRR이 0.006667 높지만 Hit@5가 1문항 낮다. 미세한 차이로 단정하지 않는다. 기업당 질문 수가 모두 5개라 이번 기업 macro 평균은 전체 질문 평균과 같다.

표의 시간은 공통으로 측정한 arm별 실행시간 중 해당 후보가 사용하는 arm의 시간과 결합시간을 더한 값이다. 매 비율의 독립 운영 요청을 다섯 번 실행한 값은 아니다. CPU 질문 임베딩·검색은 포함하나 OpenDART 다운로드, 문서 인덱싱, 서버 통신, LLM 답변 생성은 제외한다. 하이브리드 세 비율의 미세한 시간 차이는 품질 선택 근거로 쓰지 않는다.

CPU E5 문서 임베딩 준비 합계는 약 127.71초, 모델 로드는 0.23초, 파라미터 메모리는 448.8 MiB였다. 이미 캐시된 모델의 실행이며 최초 다운로드·프로세스 전체 RAM peak·GPU VRAM은 측정하지 않았다. Qwen GPU 설정은 변경하지 않았다.

LLM·OpenAI 임베딩 호출은 각각 0회라 해당 API 과금은 없다. 로컬 CPU·RAM·전력 소비와 OpenDART 호출 제한은 별도이며, 금액은 측정하지 않았다. 용량만 보면 이번 문서 5건에 삭제 정책을 강제할 근거는 없다.

8. 한계·재현·남은 판단

5기업·25질문은 독립 holdout이나 실사용 로그가 아니고 한 사업연도만 다룬다. 기업별 5문항, 위험·연구개발 유형별 2문항 등 표본이 작다. 통계적 유의성, 다른 업종·연도·장문 질의 일반화는 확인하지 않았다. 첫 두 회사에서는 E5 단독이 상대적으로 강하고 추가 회사에서 BM25가 보완했으므로, 처음 설정한 기준선만 보고 결론내리지 않는다.

정답은 알려진 특정 인용문을 완전히 포함하는 청크로 정의했다. 의미가 같은 다른 구간이나 여러 청크를 합친 근거는 자동 인정하지 않는다. 중복 인용문의 청크 개수도 Recall에 영향을 준다. 이번 지표는 최종 답변 정확도·근거 충실도·투자 분석 유용성 점수가 아니다. 청킹 자체도 고정했으므로 parent-child 청킹의 우위는 아직 알 수 없다.

추출 코드의 & 처리와 문서·질문 범위가 28번과 달라, 이전 보고서 숫자와 단순 전후 개선률을 계산하지 않는다. 29번 내부의 동일 조건 비교가 판단 근거다. 다음에는 가중치 최종 채택 보류와 별개로 사용할 임시 기준선에 합의하고, 이미 요청된 제목 경계 청킹과 parent-child 비교에서 근거 회수·순위·문맥 크기를 확인할 수 있다. 새 notebook이나 통합 구현은 별도 요청 전까지 진행하지 않는다.
