# FinSight 제품 로드맵

## 목적

이 문서는 FinSight의 기능 범위를 한 번에 구현하지 않고, 검증 가능한 제품 단위로 나누기 위한 기준이다. 버전 번호는 Git 브랜치나 배포 버전이 아니라 제품 범위의 이정표를 뜻한다.

각 버전은 이전 단계의 품질·운영 기준을 확인한 뒤에만 다음 단계로 넘어간다. 기능 수나 Agent 수를 늘리는 것은 완료 조건이 아니다.

## 공통 제품 원칙

- 투자 추천, 매수·매도 판단, 목표주가는 제공하지 않는다.
- 모든 주요 수치와 문서 주장은 출처·기간·계산 근거를 확인할 수 있어야 한다.
- 공시와 주가 변화를 함께 보여줄 수는 있지만, 근거 없는 인과관계를 주장하지 않는다.
- 실패한 조회, 누락 데이터, 근거 부족은 숨기지 않고 결과에 표시한다.
- 최종 구조는 단일 workflow와 multi-agent workflow의 정량 비교로 선택한다.

## V1 — OpenDART 근거 기반 리서치

### 사용자 가치

투자 스터디 구성원과 초급 개인 리서처가 비금융 상장기업 여러 곳의 재무 추세와 관련 공시를 출처와 함께 비교·확인한다.

### 범위

- 비금융 상장기업의 단일·다기업, 다년도 재무정보와 결정적 지표 계산
- 다기업의 최신 공통 사업연도 선택과 연결·별도 기준 표시
- OpenDART 공시 목록·원문 링크와 사업보고서 RAG 근거 제시
- 질문에 필요한 조회·계산·검색 단계, 근거와 실패 사유 표시
- 구조화된 Evidence Packet을 사용한 리서치 결과 생성

### 제외 범위

- 시장 가격·거래량 데이터
- multi-agent workflow
- API 서버와 대시보드
- 개인화 투자 추천

금융·보험업은 V1의 비금융 지표·해석 체계를 그대로 적용하지 않는다. 금융업 전용 지표·평가·문서 근거 설계는 V1 완료 후 별도 범위로 승인한다.

### 다음 단계 전환 조건

- V1 요구사항과 평가 계획을 합의한다.
- 고정 평가셋으로 재무·계산·Router·근거 품질을 측정한다.
- 선택한 단일 workflow가 문서화된 완료 기준을 충족한다.

상세 내용: [V1 요구사항](v1/REQUIREMENTS.md), [V1 평가 계획](v1/EVALUATION_PLAN.md)

## V2 — 시장 맥락 결합

### 사용자 가치

공시일 전후의 가격·거래량 변화를 공시와 같은 시간축에서 확인한다.

### 범위

- 시세 제공처의 인증·이용 조건·데이터 범위 검증
- 공시일 전후 지정 거래일의 가격·거래량 조회
- 기간 수익률과 거래량 변화의 결정적 계산
- 공시와 시장 변화를 함께 제시하되 관찰 사실로만 서술

### V1 대비 추가 검증

- 시세 데이터의 날짜·종목 매핑 정확성
- 거래일 누락과 휴장일 처리
- 데이터 제공처별 이용 조건과 API 오류 처리
- 공시-주가 인과 단정 방지 여부

### 금융업 확장과의 관계

금융업 확장은 시장 데이터 결합과 다른 데이터·지표·평가 문제다. V1 이후 금융업 전용 분석을 V2에 포함할지, 별도 버전으로 분리할지는 필요한 공식 데이터와 사용자 가치를 확인한 뒤 결정한다. V1의 비금융 지표를 금융업에 그대로 재사용하지 않는다.

## V3 — 검증된 Multi-Agent Research

### 사용자 가치

복합 질문에서 재무·공시·시장 조사를 역할별로 수행하고, 근거 검증을 거친 결과를 제공한다.

### 범위

- Coordinator가 질문을 조사 작업으로 분해
- 재무·공시·시장 조사 역할이 구조화된 Evidence Packet 반환
- Calculator는 결정적 계산만 수행
- Validator가 출처, 수치, 지원되지 않는 주장을 검사
- Synthesizer가 검증된 근거만 사용해 결과 작성

### 채택 조건

multi-agent 구조는 재무·계산 정확도, 근거 충실도, 작업 완료율 같은 핵심 품질 guardrail이 단일 workflow 기준선보다 저하되지 않는다는 조건을 먼저 충족해야 한다. 그 상태에서 Action/Route 선택 정확도, 복합 작업 완료율 또는 운영 효율 중 의미 있는 지표를 개선할 때만 채택한다. 개선이 없으면 V1/V2의 단일 workflow를 유지한다.

## V4 — 사용자 제품화

### 사용자 가치

사용자가 기업·질문·근거·실행 경로를 한 화면에서 확인하고 재현할 수 있다.

### 범위

- 분석 요청과 결과를 보여주는 대시보드
- 사용한 데이터 원천, 문서 링크, 계산식, Agent 실행 경로 표시
- 실패·재시도·근거 부족 상태의 사용자 안내
- 재현 가능한 실행·배포 방법 정리

### 시작 조건

- V1~V3 중 평가로 선택한 workflow가 확정되어 있다.
- 화면별 사용자 흐름과 승인된 UI 레퍼런스가 있다.
- 데이터 키 관리, 오류 처리, 비용·성능 제약을 정리했다.
